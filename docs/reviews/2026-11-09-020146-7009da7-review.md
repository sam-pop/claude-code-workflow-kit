### Standards
- [ ] [90] **Blocking (Data)** `scripts/install.sh:161`: `--upgrade` copies the kit's `UPGRADE.md` over `$TARGET/UPGRADE.md` without checking for an existing one.
  - Reproduced: a target holding `# Our own upgrade guide for v2 of our product` came out as `# Upgrade the kit in this repo`.
  - `UPGRADE.md:12` (step 7) then tells the merge session to delete the file. `doctor.sh:88` would also warn forever in any repo that has its own `UPGRADE.md`, which is common in libraries.
  - → Put the prompt at a kit-owned path (for example fold it into `.claude/kit-upgrade.md` and say "Read .claude/kit-upgrade.md"). Or write `UPGRADE.kit.md` / refuse when an `UPGRADE.md` exists that isn't the kit's. Update doctor (j) to match.
- [ ] [88] **Blocking (Security)** `scripts/codex-review.sh:117-121` vs `:82`, `:90`, `:158`: gitleaks scans only `$tmp/wt`, but the prompt sent to OpenAI includes the raw diff, removed lines and all.
  - Reproduced: a branch that deletes `config.txt` holding `API_KEY=sk-live-…`. The worktree no longer has the file, while the prompt (line 92) contains `-API_KEY=sk-live-abcdef…`.
  - Deleting a leaked key is a "secrets" change, so it is High-risk by definition, which is exactly when this review runs. Release mode has the same gap.
  - This breaks Q4 ("refuse on findings in what Codex would read").
  - → Also scan the diff (`gitleaks stdin < "$tmp/diff.txt"`, or scan `$tmp/prompt.md` after it is built) and exit 5 on any finding.
- [ ] [75] **Security** `scripts/codex-review.sh:18-20`, `README.md:218`, `README.md:446`, `docs/rollout.md:52`: "git-ignored files such as .env never reach it" claims more than the mechanism gives. The worktree only changes Codex's working directory:
  - Its `.git` file names the real checkout (stub saw `gitdir: …/rv/t1/.git/worktrees/wt`).
  - git commands inside it reach all history and refs (`git log --all` from the worktree saw the "add key" commit).
  - As far as I know, Codex's `read-only` sandbox limits writes, not reads; it can read the whole filesystem. So the real `.env` or `.git/kit/stuck-*.patch` is one `cat` away for a prompt-injected diff.
  - → Either state the real guarantee ("kept out of Codex's working directory; the read-only sandbox can still read what your user can read"), or tighten it: build the tree with `git archive HEAD | tar -x` plus `git init` (no link to the real repo or its history), then apply the patch.
- [ ] [88] **Errors** `scripts/codex-review.sh:82`, `:90`, `:107`: plain `git diff` follows the user's git config. Reproduced with uncommitted changes:
  - `diff.noprefix=true` → `error: glossary.md: No such file or directory … could not apply the working-tree changes`, exit 1.
  - `color.ui=always` → `No valid patches in input`, exit 1. ANSI codes would also end up in the prompt.
  - `diff.external` breaks it the same way.
  - High mode is unusable for these users.
  - → Use `git diff --no-color --no-ext-diff --src-prefix=a/ --dst-prefix=b/` on all three calls.
- [ ] [88] **Logic / docs** `scripts/install.sh:105-111`, `README.md:436`, `HOW-TO-USE.md:87`: the manifest keeps the old kit hash, but the classifier never checks whether the kit's own copy changed. A tailored file gets a new `.kit` and a merge entry on every upgrade.
  - Reproduced: a second `--upgrade` with an identical kit wrote `CLAUDE.md.kit` again.
  - In a tailored repo nearly every kit file counts as tailored (`set-models.sh` alone edits all four agents), so "later upgrades are quiet" is false.
  - → When `old.get(rel) == kit_hash[rel]` and the target differs, list it as tailored with the kit unchanged and write no `.kit`. Or drop the "quiet" claim.
- [ ] [85] **Logic** `TAILOR.md:29` with `scripts/codex-review.sh:22`: Review-only is told to copy `codex-reviewer.md` and `codex-review.sh` into the separate review workspace.
  - The script `cd`s to its own repo root and diffs that repo (`git merge-base`, `worktree add HEAD`), so it reviews the workspace, never the client checkout or PR.
  - With `pr` mode declined (Q2), cross-model review cannot work on Review-only as shipped.
  - → Remove that copy instruction and say cross-model review isn't available on Review-only in 1.4, or put Q2 back to the owner.
- [ ] [85] **Errors** `.claude/optional/codex-reviewer.md:21-23`: the relay gets no Bash timeout guidance. Claude Code's Bash default is 2 minutes.
  - A Codex `high` review that reads surrounding code usually takes longer. So does a release run plus its `xhigh` retry.
  - The call gets killed and the relay reports a failure.
  - → Tell the relay to pass `timeout: 600000`, and bound Codex inside the script (for example `timeout 540 codex exec …`) so it fails cleanly and cleans up within the tool limit.
- [ ] [90] (minor) `scripts/install.sh:183`: when no CHANGELOG section is newer (a re-run at the same version), `kit-upgrade.md` says `(no CHANGELOG.md in the kit)` although the file exists. → Say "no changes since <v>" in that case.
