### Standards
- [ ] [85] **Blocking (Errors)** `scripts/codex-review.sh:175-176`: the review directory now has no `.git`.
  - As far as I know, `codex exec` refuses to run outside a Git repo unless `--skip-git-repo-check` is passed. It prints "Not inside a trusted directory and --skip-git-repo-check was not specified." and exits 1.
  - `--ignore-user-config` also drops any trusted-project entry that could have allowed it.
  - The stub doesn't enforce this, so the tests pass. With the real CLI every high run would exit 1, and a release run would fail on Astra, fall back, and fail again.
  - The argv the stub recorded has no `--skip-git-repo-check`.
  - → Add `--skip-git-repo-check`. The flag is documented in `codex_effort.md:130`, and it is safe here: read-only sandbox, throwaway copy.
- [ ] [88] **Errors** `scripts/codex-review.sh:108`: `git archive` follows `export-ignore` and `export-subst`.
  - Reproduced: I committed `.gitattributes` with `/docs export-ignore` and left an uncommitted edit to `docs/glossary.md`. Result: `error: docs/glossary.md: No such file or directory` / `could not apply the working-tree changes`, exit 1.
  - With a clean tree the run passes, but `docs/` is missing from the review dir, so Codex can't "Read docs/conventions.md" as the prompt tells it to.
  - `export-ignore` on `tests/`, `docs/` and `.github/` is common in published packages.
  - → Build the tree from a temporary index, which ignores export attributes: `GIT_INDEX_FILE="$tmp/idx" git read-tree HEAD && GIT_INDEX_FILE="$tmp/idx" git checkout-index -a --prefix="$tmp/wt/"`.
- [ ] [90] **Logic** `scripts/install.sh:122-126` with `:171-175`: re-running `--upgrade` before the merge is finished hides the work still pending.
  - Reproduced: upgrading a 1.3 target gave 12 tailored files and 12 `.kit` files. Re-running with the same kit gave `tailored 0  tailored (kit unchanged) 12`.
  - The rewritten `.claude/kit-upgrade.md` lists all 12 under "nothing to do". Its changelog section now says "No changes since 1.4." because `kit-version` already reads 1.4, so the 1.4 Upgrade notes (such as the SubagentStop matcher edit for a tailored `settings.json`) are gone.
  - Meanwhile the 12 `.kit` files are still on disk.
  - → Refuse `--upgrade` while `.claude/kit-upgrade.md` or any `*.kit` file exists, or add `--force`. Alternatively, classify a file that still has a `.kit` sibling as `tailored` and keep the earlier `upgraded_from`.
- [ ] [95] (minor) `TAILOR.md:29`: the repair dropped a comma, so it reads "copy … and `docs/conventions.md` into it tailor those three". → "into it, then tailor those three".
