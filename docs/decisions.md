# Decisions

Decisions only. One line each, newest first, dated. No analysis, no options considered, no open items (those are in `open.md`). When an open item is decided, add it here with its ID and remove it from `open.md`.

Format: `- YYYY-MM-DD (was Oxx) — the decision, stated so it can be checked against the code.`

These are the design records for the kit itself. Each cites its evidence where one exists.

## Engineering

- 2026-11-10 — The root `scripts/check.sh` runs markdownlint-cli2 through its API with `noImport: true` (the CLI has no flag), so no JavaScript named by a config in the linted tree is loaded, and fails with exit 1 when files under `.tools/` or `node_modules/` are tracked; `tests/check.bats` enforces both. Re-check (same day): the lint step also ran code or wrote files through the other linters, so `lint_files` now passes every path as `./path` (a tracked file named `-shellcheck=<exe>` or `--preprocess=<exe>` is a file name, not an option), runs lychee with `--config /dev/null` (a tree `lychee.toml` `preprocess` command is never read) and markdownlint with `noGlobs` and `optionsOverride {fix: false}` (a tree config can neither add files outside the repo nor rewrite files). actionlint's config and shellcheck's `.shellcheckrc` cannot name an executable. `tests/check.bats` covers each.
- 2026-11-10 — The documented trust boundary for an outside branch is every file the hooks, linters, formatters, tests or build execute, not only `.claude/` and `scripts/`; a tailored `scripts/check.sh` should prefer linter invocations that load no code from the tree.
- 2026-11-10 — `codex-review.sh` gives the change under review no exemption: the prompt and every changed or untracked file are scanned with gitleaks' own `--ignore-gitleaks-allow`, each at its own path and as a copy named by a bare number that no path allowlist matches; files the change leaves alone keep the trusted ref's markers and path allowlists, gitleaks' default ones included (a documented residual). The working-tree patch is applied with `git apply --directory=wt` from outside the review tree, so the tree cannot become a repository whose config runs filters.
- 2026-11-10 — The Codex secret pre-scan is a best-effort guard against accidental egress, not a security boundary: it is gitleaks' pattern scan. Known blind spots: unprefixed secrets; UTF-16 and working-tree-encoding text; compressed or encrypted content (a gzip or zip holding a secret); untouched files keep gitleaks' default path exemptions; a `TMPDIR` whose path contains a default-allowlisted segment (for example `node_modules/` or `vendor/`) disables the scan, because gitleaks matches its default allowlist against the absolute path. Anything Codex may not see stays out of the repo, or the codex extra stays off. Closed in the same change: gitleaks skips content led by a known binary signature (`%PDF`, `MZ`, SQLite, gzip), so the numbered copy and a new `scan/named/<n>/<file name>` copy (which keeps path-scoped rules such as `nuget.config` and `.npmrc` working under an allowlisted directory) are written after a newline, and the working-tree patch is applied with `apply.whitespace=nowarn`. The refusal still lists up to 100 numbered files (an echo of attacker-chosen names, truncated and made printable; not capped further).
- 2026-11-09 — `codex-review.sh` trusts only commits on the base branch: the trusted ref (the merge-base in high mode, the start ref in release mode, the merge-base with the base in plan mode) must be an ancestor of `origin/$BASE_BRANCH`, or of the local `$BASE_BRANCH` when there is no remote-tracking copy, else exit 2. `release` without a ref starts from the newest tag on the base; plan mode refuses a local base at HEAD as high mode does. Without a remote-tracking base the local base is trusted by definition. The review tree is exported with every configured filter driver's smudge off, and the change under review gets no exemption from the secret scan (see the 2026-11-10 entry on `--ignore-gitleaks-allow`).
- 2026-11-09 — Every inline Python in `template/` and `scripts/install.sh` runs as `python3 -I`, so a `json.py` or `re.py` in the working directory is never imported; `tests/consistency.bats` enforces it.
- 2026-11-09 — Codex reviews the plan when the codex extra is on: `scripts/codex-review.sh plan <file>` sends only the blueprint text (no repository files, no diff) with a short plan-review prompt, under the same egress controls as the other modes (gitleaks scan of the prompt, `gpt-6.1-sol` at `high`, read-only, ephemeral). The main session runs it after the planner and before the owner's question round and shows its objections next to the planner's questions; it never blocks. The reviewer relay's guard allows `plan <path>` for a relative path inside the repo only.
- 2026-11-09 — The writer ladder raises effort only and never changes the model, so an escalated writer cannot land on the reviewer's model. lite and standard: sonnet/high, then sonnet/xhigh, then stop. max: opus/medium, then opus/high, then opus/xhigh, then stop. Evidence: the measured gain came from re-running failures at higher effort; switching models mid-ladder was never measured (`docs/research/coding-agent-model-effort-combos.md`). The High risk tier changes only the reviewer's effort (xhigh), never its model.
- 2026-11-09 — The model that wrote the code never reviews it. Profiles (planner, writer, reviewer, security-auditor; model/effort): lite sonnet/high, sonnet/high, opus/medium, opus/high; standard opus/high, sonnet/high, opus/high, opus/xhigh; max opus/high, opus/medium, fable/high, fable/high. The standard writer changes from opus/medium to sonnet/high and the reviewer stays on Opus; max moves Fable from the planner to the reviewer. `scripts/check.sh doctor` warns when `reviewer.md` and `writer.md` carry the same `model:`. Evidence for self-preference: the 2026-10-25 reviewer entry below; no Fable-vs-Opus comparison exists for reviewing, so max stays experimental.
- 2026-11-09 — This repo runs profiles, stop-warning, verify-review and metrics, and leaves codex off: this repo exercises the extras it ships, and with codex off no code leaves for OpenAI.
- 2026-11-09 — The session-to-session `handoff.md` and `docs/glossary.md` are removed from the kit: nothing forced the handoff to be written, and a glossary of one-line terms duplicated what the docs and `docs/decisions.md` already say. Both show as retired in upgraded repos and their files stay as the repo's own. Handing work to another agent or person is a paragraph in `template/HOW-TO-USE.md` (a brief status note pointing at `docs/decisions.md` and `docs/open.md`). This repo keeps a git-ignored `handoff.md` for the maintainer.
- 2026-11-09 — The kit is a core plus opt-in extras. Core: the process, the agents, `scripts/check.sh`, doctor, the lint hook and the review capture hook. Extras (all off in a fresh install): `codex`, `profiles` (model profiles, risk-scaled review effort, the writer ladder, the repeated-failure counter), `stop-warning`, `verify-review`, `metrics`. An extra is its files: dormant in `.claude/optional/`, active at `.claude/agents/<file>.md` or `scripts/<file>.sh`. `scripts/extras.sh on|off|status|sync` moves the files and adds or removes only the kit's own hook entry in `.claude/settings.json` (other entries kept; the file is re-written with 2-space indentation). Core scripts call an extra's script only when it is active. `scripts/install.sh --upgrade` resolves an extra's files through `active_path`, so a repo keeps what it had on (a 1.5 repo keeps all of its extras; a 1.4 repo gets profiles and metrics on and stop-warning and verify-review off), then runs the kit's `extras.sh sync`. Rejected: everything installed active with flags in a committed file, because off would be a flag instead of absence and every repo would carry every extra script and a Stop hook. The kit is a baseline for good practice, not a replacement for a repo's own workflow.
- 2026-11-09 — In this repo only (not `template/`), `git push` is an ask rule instead of a deny rule, so every push, release tags included, shows the maintainer an approval prompt. Installed repos keep the deny.
- 2026-11-09 — The `max` profile and `gpt-6-astra` for release reviews stay, labelled experimental in README, `docs/rollout.md`, `scripts/set-models.sh` and `scripts/codex-review.sh`: no comparative Fable-vs-Opus data exists for planning or auditing, and Astra rests on one secondhand non-coding benchmark. `pin()` is removed from `codex-review.sh`: it only guarded constants.
- 2026-11-09 — `permissions.deny` blocks what an agent should never do unasked (push, merge, open a PR, move or delete branches and refs, delete, edit, create-and-push or sync the GitHub repo) and stops there: no blanket `git -C`/`git -c` or `gh repo` rules, which block read-only commands and only stop deliberately reworded ones. Deny rules prevent accidents, not attacks.
- 2026-11-09 — `doctor` warns, not fails, when a tailored repo still has the `TAILOR.md` CI gate, so repos tailored on 1.4 don't go red on upgrade.
- 2026-11-09 — `scripts/codex-review.sh` sends nothing without gitleaks (exit 3), refuses (exit 5) when its own script or `codex-reviewer.md` differ from the trusted base, builds the Codex prompt from the trusted base's `reviewer.md` (so routine edits to the reviewer's lists don't block), prefers `origin/<base>` for a branch name and refuses a local base at or ahead of HEAD. The tooling check runs inside the script it protects: an accident guard, not an attack boundary; the Claude reviewer at High risk is the control. Evidence: the 1.5 adversarial audit (A1–A3, reproduced).
- 2026-11-09 — Maintainer tools are pinned, never fetched at whatever version is current: bats, bats-support, bats-assert and markdownlint-cli2 through `package-lock.json` (exact versions); shellcheck, shfmt, gitleaks, lychee and actionlint through `scripts/tools.sh`, each download checked against a sha256 written in the script before it is unpacked. One gitleaks version everywhere, enforced by `tests/consistency.bats`. Evidence: supply-chain practice of pinning by digest (as GitHub recommends for actions by full commit SHA).
- 2026-11-09 — The installable payload lives under `template/`; `scripts/install.sh` copies `template/` as is, and the repo root is an ordinary install of it (`scripts/install.sh .`), tailored to the kit. The kit runs its own workflow and checks; `tests/consistency.bats` fails when the root copies drift from `template/` in an unexpected way.
- 2026-11-09 — Scripts that run in target repos need python3 3.8 or later with the standard library only; no pip packages. Every target already has python3 on macOS and Linux; a package install would be a new step that fails silently.
- 2026-11-09 — Shell scripts target bash 3.2 with BSD and GNU userland: no `mapfile`, `declare -A`, `local -n`, `${x,,}`, `[[ -v`, `|&` or `coproc`. macOS ships `/bin/bash` 3.2, and hooks run with whatever `bash` is on PATH. CI runs the tests under macOS `/bin/bash` 3.2. Evidence: the 1.4 review cycle replaced a `mapfile` call in `scripts/check.sh` `lint --changed`, which bash 3.2 does not have.
- 2026-11-09 — Cross-model review (Codex) is off by default and never blocks. It sends diffs to a second vendor, and no study measures the extra true defects it finds; its value is in disagreement. Evidence: `docs/research/coding-agent-model-effort-combos.md` ("Codex earns a seat as a dissenting opinion, not a gate").
- 2026-11-09 — Model profile for this repo: standard (`scripts/set-models.sh standard`). Cross-model review: off.
- 2026-10-25 — An unconfigured check fails (exit 2, `NOT CONFIGURED`) instead of passing or skipping, so no report can say "lint passed" for a check that never ran. A check that does not apply is replaced by an explicit `skip "<reason>"`. Practice: agents claiming verification that did not happen (README, Why this exists: Claimed verification).
- 2026-10-25 — The reviewer reads the diff before the plan, in a separate context with no edit tools. Evidence supports the fresh context: a model favours its own output when it grades it (`docs/research/coding-agent-model-effort-combos.md`, "Review quality collapses below medium": self-preference of 50–75% on code tasks, measured with open models as judges; later work attributes much of it to evaluator uncertainty). Reading the diff before the plan is a design choice: no cited study tests anchoring on a plan.

## Retired

- 2026-11-09 (superseded 2026-11-09, effort-only ladder above) — The writer escalates to a fresh writer one rung up instead of retrying in the same context, and the ladder ends after three rungs. Evidence: `docs/research/coding-agent-model-effort-combos.md` ("A medium-to-high ladder beats fixed high on price and pass rate": escalating only failures was cheaper and solved more). That a failed context carries the framing that failed is labelled speculation in the source (`effort_economics_escalation.md`), not evidence.
